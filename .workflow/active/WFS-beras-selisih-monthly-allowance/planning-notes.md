# Planning Notes

## User Intent
GOAL: Beras yang memiliki selisih harus ikut diinput ke Monthly Allowance/Deduction, mirip penginputan tunjangan/potongan yang sudah ada.

SCOPE: Pelajari dan rencanakan implementasi sebelum coding.

CONTEXT: Alur beras saat ini sudah menghitung selisih, tetapi input payroll AD Lists belum mengisi dimensi akun seperti Machine Code dan Expense Code. Dimensi tersebut sudah ada di alur Task Register melalui parsing ChargeJob.

## Context Findings
- Current payroll monthly allowance/deduction runner is `browser-automation-engine/payroll-runner.js`, using `templates/payroll-ad-input.json`.
- Current beras preparation is `prepareBerasAutomationData()` in `backend/services/payrollAutomationService.js`.
- Existing beras endpoint `/api/payroll/beras/run` already invokes `payroll-runner.js` with `current_payroll_beras_data.json` and `--component-key=beras`.
- Task Register account dimension flow is in `browser-automation-engine/templates/_charge_job_input.json` and action `parseChargeJob`.
- Task Register HTML confirms selectors for account dimensions:
  - Station Code: `#MainContent_MultiDimAcc_ddlBlock`
  - Machine Code: `#MainContent_MultiDimAcc_ddlSubBlk`
  - Expense Code: `#MainContent_MultiDimAcc_ddlExpCode`
- Existing action `retryInputWithValidation` has special hidden-select logic for Expense Code, so it should be reused instead of typing text blindly.
- Current beras mapping has a conflict:
  - `backend/config/payroll-comparison-config.json` maps beras to `AL0012`.
  - `backend/services/payrollComponentMapping.js` and discovered mapping currently use `AL0011` as TUNJANGAN TRANSPORT for beras.
  This must be confirmed before execution.

## Worktree Risk
The repo has pre-existing modified and untracked files in backend, frontend, and browser automation areas, including the same files likely needed for implementation. Treat all as intentional WIP and avoid overwriting unrelated changes.

## Planning Decision
Prefer reusing the existing payroll monthly allowance path:
- Keep selisih beras generated by backend.
- Add charge job/account dimension data to payroll payload.
- Extend payroll AD template/runner to fill Station, Machine, and Expense before Add/Save.
- Avoid maintaining a separate beras-only runner unless the generic payroll runner cannot support the dimension fields.
